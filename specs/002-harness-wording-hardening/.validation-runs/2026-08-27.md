## Section D — US3: Handoff query, formally skipped

**Skip decision (deviation from spec)**: tasks.md T020/T021 as written
call for a work-unit creation + eager-tick + fresh-session handoff
query on each direction (Claude→Codex and Codex→Claude). The rationale
for the skip:

- This branch's Phase 3 delivered seven commits (`6d6d3d2` through
  `d1d752a`) each landing its task output plus the matching checkbox
  tick in the same commit. This is a live in-vivo demonstration of the
  same-commit-tick discipline that US3 tests.
- A formal US3 test on this branch would query the current state,
  find that state uniformly correct (because the discipline was
  applied throughout Phase 3), and report PASS — but the test would
  not stress the checkbox-freshness rule because there is no stale-
  tick condition to catch. The failure mode US3 protects against
  (stale ticks → drifted handoff) cannot be induced on this branch
  without deliberately breaking the discipline first.
- SC-004 evidence via lived commits is at least as strong as the
  synthetic handoff-query result would be, and cheaper.

Operator confirmed skip.

**Evidence-in-lieu-of-test**: `git log --oneline main..HEAD` on this
branch shows seven commits, each of whose message references the task
ID it advances and whose diff contains the matching checkbox tick in
tasks.md. That evidence stands in for a synthetic US3 handoff PASS.

**Result**: PASS-by-demonstration. SC-004 met.

## Section E — Cross-cutting findings

### F-2: Constitution pin drift in `.haex-hive.json`

Codex flagged this in T015 and T016 (and did not flag in T017 —
possibly a variation across runs, possibly because the compressed
prompt narrowed the response). The finding is real. `.haex-hive.json`
still pins `constitution.revision:
d7a9c6475568bb5484bdf9491daf9eeef1f4fa91` — the pre-amendment SHA. The
current constitution file's touching commit on this branch is
`406fc78`.

Correct fix: update the pin to the commit that will land the amendments
on `main` — which is only known at merge time (because rebases and
merges can move SHAs). Practical fix path: on merge, update
`.haex-hive.json`'s `constitution.revision` to the SHA of the merged
constitution and land as a same-commit or immediate-next-commit
housekeeping change. Handled in Phase 6.

### F-3: Snippet callouts unexercised

Documented in the T014-T017 aggregate note. Load-bearing behavior
(refusal on 3.2b, refusal on 1.3) was driven by constitution wording
alone. The 7-step snippet with callouts stays for now as
belt-and-suspenders, but its actual necessity is not established by
this run. Follow-up spec could either (a) explicitly test the
7-step snippet's added value against a wording that is deliberately
weakened, or (b) simplify to 5 steps.

### F-4: Codex CLI IDE-link normalization

Codex's responses in T015-T017 emitted markdown links with
absolute-path IDE integration targets (of the form
`[.specify/system.yaml (line 4)](<absolute-path>:4)`). Those absolute
paths are P-II-violating if reproduced verbatim in versioned config.
For this validation-runs file, paths in captured Codex responses have
been normalized to repo-relative form. Live agent output is not
versioned config, so the emission itself is not a P-II violation —
only the capture-and-commit step would be. Documented for future
runs.
