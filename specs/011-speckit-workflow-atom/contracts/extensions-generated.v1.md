# Generated Extensions Contract v1 (install output)

**Spec**: [Spec 011 simplified](../spec.md)
**Referenced by**: FR-005 (reviewer-hardened in PR #54)

Deterministic output written to `.specify/extensions.yml` on every `haex install`. Regenerated from scratch; removed or downgraded molecule entries never survive as stale output.

## File location

`.specify/extensions.yml` (repository root, alongside `.specify/` sibling directories).

## Ownership boundary

- **Generated by the runtime**: authored solely by `haex install`. Every install overwrites the file.
- **NOT operator-editable**: an operator who edits this file loses those edits at the next install. The file's top opens with a comment declaring itself as generated so accidental edits are visible.
- **Inputs**: (a) the adopted workflow molecule's `atoms.extensions` fragment (if any); (b) the consumer-owned `.specify/extensions.local.yml` (if present).

## Shape

```yaml
# generated by haex install: do not edit; edit .specify/extensions.local.yml or adopt a workflow molecule instead

installed:
  - v-model-extension-pack
  - speckit-companion

settings:
  llm_endpoint: "http://localhost:8080"
  retry_count: 3

required_extensions:
  - id: acme-internal-linter
    version_constraint: ">=2.0.0"
    homepage: https://acme.corp/tooling/speckit-linter
    sources:
      - origin: local
        kind: required
  - id: v-model-extension-pack
    version_constraint: ">=0.7.2"
    homepage: https://speckit-community.github.io/extensions/v-model-extension-pack
    sources:
      - origin: molecule
        molecule_id: com.example.publisher.strict-tdd-workflow
        molecule_revision: aabbccddeeff00112233445566778899aabbccdd
        kind: required

optional_extensions:
  - id: speckit-companion
    version_constraint: ">=0.21.0"
    sources:
      - origin: molecule
        molecule_id: com.example.publisher.strict-tdd-workflow
        molecule_revision: aabbccddeeff00112233445566778899aabbccdd
        kind: optional
      - origin: local
        kind: optional

hooks:
  before_specify:
    - extension: strict-tdd
      command: speckit.strict-tdd.pre-spec
      script: .specify/extensions/workflow-molecules/com.example.publisher.strict-tdd-workflow/pre-implement.sh
      description: "Enforce TDD prerequisites before specification"
      enabled: true
      optional: true
      prompt: "Verify TDD prerequisites?"
      origin: molecule
    - extension: acme-internal
      command: acme.internal.spec-guard
      script: hooks/local/spec-guard.sh
      description: "ACME internal spec-guard check"
      enabled: true
      optional: false
      origin: local
```

## Field rules

- Top-of-file comment MUST include the phrase `generated by haex install: do not edit`.
- `installed[]` and `settings` are passed through verbatim from the consumer-owned local source (if present).
- `required_extensions[]` and `optional_extensions[]` are the merge output. Each entry carries a `sources[]` list naming every side that contributed and its declared constraint kind. Deterministic sort order: by `(id,)`.
- `hooks.<stage>[]` merged per stage. molecule entries first (in molecule-fragment declaration order), local entries after. Identity-matching (per R8) local entries REPLACE the molecule entry in its position. Each hook entry carries an `origin: molecule | local` field for provenance.

## Non-persistence rule

The generated file is NEVER used as an input to the next install. Every install rebuilds it from `.specify/extensions.local.yml` + the currently-adopted workflow molecule's fragment. This means:

- Removing the workflow molecule -> the molecule's entries disappear from the next `.specify/extensions.yml`.
- Downgrading to a smaller fragment -> the removed sub-declarations disappear.
- Editing `.specify/extensions.yml` directly -> edits are silently lost at the next install.

## Deterministic serialisation

- YAML with 2-space indent, LF newlines, no trailing whitespace.
- Key order at the top level: `installed`, `settings`, `required_extensions`, `optional_extensions`, `hooks`.
- Within each object entry, keys are sorted alphabetically.
- Lists retain the ordering rule that governs their content:
  - `installed[]`: as declared in local source.
  - `required_extensions[]` / `optional_extensions[]`: sorted by `id`.
  - `hooks.<stage>[]`: molecule-first + local-last with identity-replace.
