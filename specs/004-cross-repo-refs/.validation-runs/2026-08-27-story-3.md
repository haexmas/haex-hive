## Story 3 — Malformed config rejected before harness work starts

Each case starts from a scratch copy of the real `.haex-hive.json`, mutates
one field, then runs `spec-resolve status` (the same call the session-start
snippet makes). Expected: exit 2 + pinpointed stderr per malformation.

### Case 1 — unknown role

```
$ /home/haex/Projekte/haex-hive/.specify/scripts/spec-resolve status
spec-resolve: /tmp/spec-004-invalid-test/.haex-hive.json: harness_sources[0].role unknown value 'definitely-not-a-real-role' (valid: constitution)
exit: 2
```

Pinpoints `harness_sources[0].role`, names the invalid value, and lists
the valid set. ✓

### Case 2 — missing revision
